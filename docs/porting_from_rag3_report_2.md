# Master Walkthrough: Advanced RAG Porting & Custom Graph Integration

Этот документ представляет собой всеобъемлющий отчёт о проделанной работе по переносу стратегий портирования из Go-прототипа (согласно [docs/porting_from_rag3.md](file:///f:/projects/APL-RAG/docs/porting_from_rag3.md)) в Rust-продакшен (`tensor-rag`), а также о создании и интеграции кастомного графового модуля и его визуализации на фронтенде.

---

## 1. Внедрение возможностей из Porting Guide (Бэкенд RAG3)

Была выполнена адаптация и перенос ключевых алгоритмов поиска, чанкования и пост-обработки из прототипа RAG3:

### 1.1. Трёхуровневое иерархическое чанкование

- **Логика чанкования (`chunker.rs`):** Реализован `HierarchicalChunker`, который разбивает исходный текст на 3 уровня с сохранением родительских связей:
  - **Macro (глава/раздел, ~2048 токенов):** Верхнеуровневый контекст для модели.
  - **Medium (абзац, ~512 токенов):** Первичная поисковая мишень.
  - **Micro (предложение, ~128 токенов):** Точное смысловое попадание.
- **Границы и перекрытие:** Чанкование осуществляется по естественным границам текста (Markdown-заголовки `#`, implicit-заголовки PART/Глава, ALL-CAPS строки, границы предложений и таблиц). Внедрён token-aware overlap для связности контекста.

### 1.2. Расширение схемы PostgreSQL & Qdrant

- **База данных (`db.rs`):** Расширена таблица `documents` для поддержки новых полей: `chunk_level`, `parent_chunk_index`, `macro_index`, `medium_index`, `header_chain` (JSONB-массив заголовков), `zone_keywords` и `entities`.
- **Индексы:** Настроены GIN-индексы для быстрой фильтрации по массиву сущностей и древовидным путям.

### 1.3. Анализ сущностей и нормализация

- **Модуль извлечения сущностей (`entity.rs`):** Реализован легковесный анализатор именованных сущностей (Named Entities) и сущностей запроса (Query Entities) с объединением на основе light stemming.
- **Конвейер нормализации (`normalizer.rs`):** Внедрена обработка склейки дефисов, коллапса пробелов, удаления стоп-слов (RU/EN) и стемминга для точного подсчёта частоты термов.

### 1.4. Алгоритм гибридного поиска RSF (Relational Search Fusion)

- **Поисковый планировщик (`rsf.rs`):** Создан модуль планирования и исполнения RSF, объединяющий скоринг по трем каналам:
  - **Vector (Dense):** векторная близость E5.
  - **BM25 (Sparse):** точное совпадение ключевых слов в PostgreSQL.
  - **Entity Channel:** бустинг документов на основе совпадения извлечённых сущностей.
  - Нормализация оценок методом Min-Max.
- **MMR и RRF (`vm.rs`):** Добавлен полноценный реранкинг по методам Maximum Marginal Relevance (разнообразие выдачи) и Reciprocal Rank Fusion.
- **Parent Context Resolution (`response.rs`):** При поиске мелких фрагментов (Micro/Medium) система автоматически находит их Macro-родителей для передачи полного контекста в LLM.

## 2. Разработка кастомного графового модуля (Backend Graph)

Для моделирования связей между сегментами без использования сторонних расширений СУБД (таких как Apache AGE) был создан модуль `graph.rs`:

- **neighborhood-запросы (`get_document_neighborhood`):** Рекурсивный CTE-запрос к PostgreSQL для обхода связей в обоих направлениях от заданного документа до указанной глубины (по умолчанию 2 шага). Возвращает вершины (nodes) и связи (edges).
- **Поиск кратчайшего пути (`find_shortest_path`):** Алгоритм поиска в ширину (BFS) с использованием рекурсивного CTE для нахождения цепочки связанных документов между двумя точками.
- **Автоматическая линковка по сущностям (`auto_link_by_shared_entities`):** Фоновый анализатор, который находит пары документов, имеющих более `threshold` общих сущностей, и прокладывает между ними ребро `"shares_entities"`.
- **Каскадное удаление (`db.rs` / `graph.rs`):** Очистка связанных рёбер при удалении документа из библиотеки для предотвращения висячих связей.
- **HTTP API (`router.rs`):** Маршруты Axum для обслуживания запросов графа:
  - `GET /documents/:doc_uuid/graph`
  - `GET /documents/path`
  - `POST /documents/auto-link`
  - `GET /documents/:doc_uuid/details` (возвращает детальный состав чанков и связей)

## 3. Модернизация интерфейса (Frontend UI)

Было выполнено полное обновление пользовательского интерфейса портала `tensor-rag` для визуального представления новых возможностей:

### 3.1. Интерактивные вкладки просмотрщика

В центральной панели просмотра документа добавлен блок вкладок (Текст, Иерархия, Сущности, Граф связей) с плавной анимацией перехода и поддержкой локализации (RU/EN).

### 3.2. Дерево иерархии документа (Hierarchy Tree)

- Позволяет увидеть структуру чанков (`Macro` → `Medium` → `Micro`).
- Реализовано интерактивное раскрытие ветвей по клику на заголовки.
- Узлы окрашены соответствующими бейджами уровней и выводят цепочки контекстных заголовков и ключевые слова.

### 3.3. Облако сущностей и ключевых слов (Entities Explorer)

- Выводит частотный Tag Cloud извлечённых из документа именованных сущностей и ключевых слов.
- Клик по тегу фильтрует поисковую выдачу в библиотеке слева.
- Клик по кнопке `[AI]` рядом с тегом открывает чат-панель справа и отправляет запрос ассистенту для подробного объяснения данной сущности.

### 3.4. Визуальный граф связей (Canvas Graph)

- Отрисовывает 2D-сеть документов на HTML5 Canvas с поддержкой ретина-дисплеев (DPR масштабирование).
- Интегрирован физический движок (силы отталкивания, натяжения пружин рёбер и гравитации к центру) с рендерингом через `requestAnimationFrame`.
- Поддерживается перетаскивание узлов мышью, интерактивный hover-эффект и клик по вершине для перехода к просмотру выбранного документа.

### 3.5. Доработки чата и настроек

- **Фильтрация TOC:** В панели чата скрыты служебные карточки оглавления поиска.
- **Цепочки хлебных крошек:** Контекстные пути источников парсятся и выводятся в виде наглядного пути (`Раздел 1 ➔ Подраздел 1.2`).
- **RSF-слайдеры настроек:** В модальное окно настроек добавлены параметры весов гибридного поиска (`RSF_DENSE_WEIGHT`, `RSF_BM25_WEIGHT` и др.) с возможностью перезапуска сервера для их применения.
