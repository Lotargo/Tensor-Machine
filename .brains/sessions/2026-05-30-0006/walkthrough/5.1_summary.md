## Task 5.1 VM Architecture Purity

Addressed a major architectural deviation where the legacy test runner `VM::run` still directly embedded database I/O mocking (specifically `RetrieveQdrant`, `RetrievePostgres`, and `IfConfidence`), violating the separation of data fetching and calculation.

- Completely stripped I/O logic out of `VM::run`. It now cleanly rejects any I/O opcodes with an explicit error.
- Refactored `lib.rs` performance benchmarks and E2E tests to rely on the unified `mcp::execute_program` orchestrator instead of `VM::run`.
- Bounded performance testing in CI to a more relaxed tolerance to account for the unified async orchestrator overhead when running the mock execution path under test mode.
